## 一、协议规则

### 1.1 登记格式（必填七字段）

每一条冻结预言必须包含以下七字段，缺一不予登记：

| 字段 | 要求 |
|---|---|
| **编号** | `BP-<序号>`（本文件首批 BP-1 ~ BP-4；后续追加 BP-5+，编号永不复用） |
| **预言内容** | 断言的完整陈述，含其当前治理级别（CLAIM / CONJECTURE，与 `proof_status.md` 同步） |
| **数值与不确定度** | 可定量部分必须给出数值与不确定度/误差界；暂不可定量者必须显式标注"暂无定量形式"而非含糊带过 |
| **证伪条件** | 可被推翻的明确条件（原文照录 `proof_status.md`，含编号①②）；证伪条件本身冻结 |
| **裁决时间窗** | 何时/何种实验或数学进展可裁决；无明确实验窗者标注窗口类型（理论裁决窗/实验窗/持续监控） |
| **登记日期** | 冻结日期 |
| **版本哈希** | 登记时的 `git rev-parse HEAD` 实取值 |

### 1.2 冻结与降级规则（核心纪律）

1. **发布后冻结**：本文件登记后，预言内容、数值、证伪条件冻结。任何对已登记预言数值或证伪条件的修改，**自动将该预言降级为"后验拟合"**并在登记表中显式改标 `STATUS: POST-HOC`，原条目保留不删除（对标 UFPF RAP"发布后任何修改自动降级为后验拟合"声明）。
2. **重新登记唯一例外**：附带新版本哈希、新登记时间戳、并说明修改理由者，可作为**新版本条目**重新登记；旧版本条目与原哈希永久保留可对照。
3. **证伪触发**：任一证伪条件被满足 → 条目标记 `STATUS: FALSIFIED`，同步登记 `framework/ERRATA_AND_NEGATIVE_RESULTS.md`，并按 `proof_status.md` 治理流程降级对应 CLAIM/CONJECTURE。
4. **验证触发**：预言获独立形式化证明或独立实验确认 → 标记 `STATUS: VERIFIED`，按治理流程晋级（CLAIM→THEOREM 标准见公理审计系列 01 §6）。
5. **与数值基准的分工**：已有 `verify_*.py` PASS 支撑的定量基准登记在 `papers/BLIND_REGISTRY.md`（S1–S8）；本文件登记的 BP 条目是**尚无独立验证链的高风险理论声明**——正因如此才更需要冻结，防止事后修饰（`papers/BLIND_REGISTRY.md` §三原有口径是"CLAIM/CONJECTURE 不在盲登记范围内，直至完成独立形式化验证"；本文件将其升级为**带冻结纪律的预登记**，两条口径互补：S 表管"已验证数值不回调"，BP 表管"未验证声明不整容"）。

### 1.3 填写纪律

- 证伪条件必须可操作（"什么观测/推导结果出现即推翻"），禁止"有待进一步研究"式空话；
- 数值断言的误差界必须来自先验论证，禁止按当前实验值反推（见 `framework/PARAMETER_DISCIPLINE.md` 标注规则）；
- 登记即公开承诺：欢迎外部按证伪条件检验。
