## 摘要

## 2 纵向整合 vs 水平扩展：方法论对比

### 2.1 两种扩展模式的定义性分界

**水平扩展**（horizontal scaling）：以新增模块数与新增定理声明数为进态度量，模块间无依赖纵深，定理间无消费关系。其极端形态即本仓库的批量生成器：每版新增 40 个模板模块 × 14–19 条定理，定理的消费者是"计数器"而非其他定理。**纵向整合**（vertical integration）：以"从已登记基础到达目标深层定理的路径长度缩短"为进态度量，新增定义与引理必须被更高层消费，否则不得入库。两者的判别不在意图而在**依赖图的形状**：水平扩展的依赖图是扁平星形（万千定理悬挂在少数定义上），纵向整合的依赖图是有纵深的有向无环图（深层定理站在多层中间引理之上）。

### 2.2 参照系：mathlib4 的组织原则

mathlib4 是纵向整合的已验证形态（mathlib Community, CPP 2020）：其类型类层次（`Monoid → Group → Ring → Field` 等）与 bundled structures 保证每个抽象层只依赖下层接口；`simp` 引理集、`norm_num`/`ring`/`aesop` 等自动化把"标准估计"压缩为声明式调用，使人力集中于定理的结构设计而非符号体力劳动。素数定理（Prime Number Theorem）项目的完成证明：当中间层（复分析、Mellin 变换、Chebyshev 估计）齐备时，深层定理的形式化成本是课程级而非奇迹级的。发展战略 §2.2 的"引理工厂模式"一词即源于此生态的一般化，本文 §3 给出其组件化定义。

### 2.3 对比表

| 维度 | 水平扩展（v10 模式） | 纵向整合（本文框架） |
|------|---------------------|---------------------|
| 进态度量 | 模块数、定理声明数 | 到达深层定理的路径长度 |
| 依赖图形状 | 扁平星形 | 有纵深的 DAG |
| 新定理的消费者 | 计数器 | 更高层定理 |
| 平凡证明的处置 | 批量生产 | 自动化压缩（tactic/simp 集） |
| 公理 | 未审计、与定理混杂 | 五层登记（01 篇 §5.1） |
| 治理指标 | "证明率"（已废止口径） | 真实证明率 + 中间层覆盖率（§6.2） |

## 3 中间层定理网络：引理工厂模式

### 3.1 中间层的结构性论证

发展战略 §2.3 的诊断是："从基础公理到深层定理之间缺乏稳固的中间层引理网络，是'大量平凡证明'反模式的根源。"其机制可陈述为：**当中间层缺失时，每个高层目标都被迫分解为一堆彼此无关联的小步骤，这些小步骤以"定理"名义入库即表现为平凡定理的堆积**——平凡证明不是作者的懒惰，而是中间层缺席的症状。反之，当中间层存在时，平凡步骤被吸收为引理网络的内部边，入库定理自然位于网络的高层节点。因此纵向整合的第一工程对象是中间层本身，而非任何单个大定理。

### 3.2 引理工厂模式的三个组件

引理工厂（lemma factory）不是"批量生成引理"（那正是水平扩展），而是**让同一类平凡推理只被证明一次、此后永远以声明式调用复用**的生产体系。三个组件：

1. **接口层定理**：每个领域模块先定义只依赖下层接口的中层结构（如 02 篇 T1.4 的"ℤ\_p 是局部环、极大理想 (p)"之于 DVR 判据），接口层定理的证明可以薄，但陈述必须稳定——它们是网络的骨架节点；
2. **标准估计库**：对反复出现的推理模式（范数估计、极限交换、有限求和界）构建可重用引理与 simp 规则集，使后续证明以一行 `simp`/`aesop` 调用闭合；
3. **tactic 宏与计算引理**：发展战略 §2.2 的"数论专用自动化"——`norm_num` 插件方向的求值规则（如 02 篇 T1.1 的 `v_p` 计算引理），把可判定计算从证明体中剥离。

### 3.3 与 mathlib4 自动化的关系

本仓库不重建 mathlib4 已有的自动化（`simp`/`norm_num`/`ring`/`aesop` 生态），引理工厂的自建增量限于**领域专用的标准估计**——例如课程链 Dirichlet 段的"系数有界 ⇒ 与 p-级数比较"（02 篇 §5.2）这类将在 T2.3、T2.5 及后续 L-函数定理中反复出现的估计模式。判据：一个推理模式若在课程链中出现 ≥ 3 次，即应被工厂化为引理/tactic，而非第三次手写。

## 4 深层定理的识别标准：非平凡性的可操作判据

### 4.1 三指标

"深层定理"（deep theorem）在治理口径中需要可操作定义。本文提出三指标，均可在 Lean 4 工程中近似测量：

1. **证明长度**（proof length）：以**内核证明项的 AST 节点数 / DAG 规模为金标准**（核验组纠正：tactic 步数是高度非不变的代理——同一命题既可一行 `by simp` 闭合也可展开为数千步内核归约），tactic 步数仅作工程参考。平凡定理的特征是常数级证明项——`True := trivial`、`a + 0 = a := add_zero`、`(0:ℝ)+0=0 := by rfl` 的证明项长度与陈述长度同阶；
2. **依赖深度**（dependency depth）：定理在引用依赖 DAG 中的最长链深度，且须区分**公理依赖**与**定理依赖**（核验组纠正：后者随库重构可变，前者才是语义负担的硬约束——与 01 篇 `#print axioms` 审计口径一致）。`True := trivial` 的深度为 0；Brouwer 不动点类定理（拓扑里程碑 P1）经"Sperner 引理 → 单纯剖分 → 组合拓扑"链条，深度显著；
3. **概念压缩率**（conceptual compression）：陈述所压缩的概念含量与证明展开规模之比。深层定理以短陈述压缩长证明（压缩率高）；同义反复定理的陈述与证明等长（压缩率 ≈ 1），如 ChernNumber 模块的 `chernNumberConvergence`（`∃ N, ∀ n ≥ N, x = x`）。**诚实标注**：该指标非证明工程标准术语，其严格化有循环定义风险（"概念含量"本身需外部本体度量，核验组指出），当前只作定性指南、不作量化门槛。

### 4.2 判据的边界与反例

三指标须组合使用，单独使用各有反例：**短证明不等于平凡**——站在大定理肩膀上的推论（如由费马大定理推出 n=4 特例）证明极短但依赖深度极大；**长证明不等于深刻**——本仓库批量模块的 200 条同义反复可以写得很长；**高压缩率不等于深层**——核验组提供的反例：Yoneda 引理式的万有构造以一行 tactic 闭合却高度压缩，而素数定理的初等证明极长但压缩率不高。依赖深度对"复用 mathlib4 深层结果"（THEOREM\* 口径，01 篇 §6.2）天然取高值，因此**概念压缩率是区分"深层"与"深依赖"的关键**：深层定理的陈述自身携带新概念含量，而纯复用推论的陈述是已有定理的特例化。de Bruijn 因子（Wiedijk）给出外部校准：健康形式化文本相对数学文本的膨胀比应有界；本仓库 6,000 万条平凡声明对应的病态 de Bruijn 因子，正是三指标同取相对低值的统计表现（核验组纠正："极小值"应修正为"同类命题中的相对低值"——`a + 0 = a` 的内核项经类型类解析后并非绝对极小）。

### 4.3 应用：里程碑定理的筛选

三指标的直接用途是为发展战略 §2.3 的里程碑序列（P0 `ℝⁿ ≇ ℝᵐ` → P1 Brouwer → P2 Jordan → P3 Seifert-van Kampen → P4 Mayer-Vietoris）与课程链定理清单（02 篇 T1.x/T2.x、03 篇 P0–P4）提供**入库门槛**：凡拟登记为"深层定理候选"者，须三指标均超阈值（阈值在校准后回填，见 O4.2）；凡三指标均取同类相对低值者，无论命名多么宏大，一律按平凡定理口径登记，不计入任何里程碑。

## 5 横断发现：20 篇模块强化论文的证据

模块强化系列（2026-08-05/06，两批共 20 篇，每篇经逐行核对 + 千界花园评议）对本仓库 20 个手工策划模块做了认识论体检。横断阅读得到三类模式，它们共同规定五阶段框架的设计约束。

### 5.1 反例 A：假公理——审计必须先于构建

两处实测证明"公理"可能是**命题为假**（而非"尚未证明"）的断言：

- `GaugeTheory.lean` 的 `GaugeCouplingUnification`（第 423 行）断言 `∃ M_GUT > 0, g3 = g2 ∧ g2 = g1`，而 `g3/g2/g1` 是固定数值 def（1.22/0.65/0.36）——即断言 `1.22 = 0.65`，`norm_num` 可证其否定，爆炸原理下全库任何命题可证（模块强化 15 篇 §3）；
- `ChernSimons.lean` 的 `alphaInverseIsChernSimonsLevel`（第 298–302 行）按现有定义展开断言 `(137.035999084 : ℝ) = 137`，与已证定理合流即推 `False`（01 篇 §4.2 A2；已于 2026-08-06 修复为误差界命题并通过编译验证）。

教训写入框架：**任何中间层构建之前，先对存量公理做"一致性体检"（逐符号代入现有定义）**——纵向整合若以含假公理的地基起步，整合越深，爆炸半径越大。

### 5.2 反例 B：零占位与审计失明——第二指标的必要性

`#print axioms` 审计存在实测盲区：**常值 def 占位**。

- `ChernNumber.lean` 六处"零占位"：`ChernClass`/`FirstChernClass2D`/`ChernNumber`/`BandChernNumber2D` 等的 `definition` 字段把第一陈类、陈形式、陈数钉死为 `0`（第 166–249 行），另有 `wedgeProduct` 以普通乘法冒充楔积（丢失反对称性）、`exteriorDerivative` 返回偏导对冒充外微分——"0 axiom 0 sorry"表象下承载 TKNN 链最重隐性债务（模块强化 14 篇 §3）；
- 同科目散布：QuantumMasterEquation 五处 def 占位（熵 `:= 0`、速率 `:= 0.5`、网络 `:= []`，18 篇）、InformationGeometry 的 Fisher 矩阵恒零（19 篇）、GaugeTheory 的 `trace_field := 1`/`energyDensity := 0`/`HodgeStar := f`（15 篇 §2.2）。

零占位的危险性在于它**不出现在 `#print axioms` 输出中**，却被下游定理当真实等式 rewrite——债务只是换了会计科目。模块强化系列的处置建议（常值 def lint：扫描 def 体为字面量 `0`/`[]`/`id`/`1` 的声明）被本文采纳为审计 CI 的**第二指标**，写入五阶段框架的阶段 ①。

### 5.3 正例：ContinuumLimit 的脚手架模式

`ContinuumLimit.lean`（模块强化 20 篇）是纵向整合的正面样板：**12 个真定理**（`scaleParameter` 的正性/趋于零/单调三定理、三个有界性定理、退化情形定理、"格点假象"定理、ε-M 形式极限链）全部有实质证明体，证明"取极限之前"各构造良定义且行为良好；**2 条公理**（`spectralConvergence`、`continuumLimitTheorem`）诚实标注为研究级开放问题并附文献坐标（Belkin–Niyogi、Singer、Coifman–Lafon）。它呈现的形态正是中间层网络的正确用法：真定理构成脚手架（必要但不充分），公理诚实承载缺口——脚手架 + 诚实债务，而非假定理 + 假完备。同批次的 CookLevin/SAT（全可计算定义 + 3 个真门级定理，零债务）与 BlochTheorem（`BlochTheorem_TranslationBehavior` 为"当日可兑现"清偿券）是另两个可复制的生长点。

## 6 五阶段实施框架

### 6.1 五阶段

- **阶段① 接口审计**：对目标模块执行公理四分类登记（01 篇 §2）+ 一致性体检（§5.1）+ 常值 def lint（§5.2）+ 双轨/字段投影清点；产出机器可读《模块债务表》。
- **阶段② 中间层接口构建**：按"接口层只依赖下层接口"原则建立中层结构与接口定理（§3.2 组件 1）；消除双轨（ChernNumber 教训：L4 自建双轨定义导致类型链断裂）。**接口稳定性契约**（采纳核验组意见）：中间层 API 冻结点须显式登记——mathlib 经验表明中间层的破坏性变更成本极高，冻结前的接口须过双人复核。
- **阶段③ 引理工厂建设**：将出现 ≥ 3 次的推理模式工厂化为引理/simp 集/tactic 宏（§3.2 组件 2–3）。
- **阶段④ 深层定理攻坚**：以三指标筛选目标（§4），按里程碑序列排期；凡依赖未登记公理者留级 CLAIM（01 篇 §6）。
- **阶段⑤ 血缘登记与持续回归**：登记"论文 ↔ Lean 模块 ↔ theorem 清单"三元组（发展战略 §5.3），纳入 CI 断链检查；`#print axioms` 抽查输出仅含标准三件套 + 已登记公理。**持续抗腐化**（采纳核验组意见）：⑤不是一次性清理而是常驻门禁——每次提交重跑断链与双轨扫描，防止类型类实例或宏展开重新引入冗余（差异回归）。

### 6.2 验收门槛（治理口径）

每阶段的通过判据：①《模块债务表》覆盖率 100%（该模块全部 axiom/常值 def/投影字段）；②接口层 import 闭包中无上层模块；③工厂化引理被 ≥ 2 个后续证明真实复用；④新登记深层定理三指标超阈值且零 sorry；⑤血缘三元组机器可读、CI 无断链。仪表盘（发展战略 §5.1）新增字段："中间层覆盖率"（被 ≥ 1 个高层定理消费的引理占比）——它把"纵向"从修辞变为季度可复盘的数字。

## 7 与课程式形式化的接口

课程链（02 篇：Zp/Qp → Dirichlet 特征与 L-函数 → Dedekind 整环；03 篇：第三环方案）与五阶段框架的关系是**内容与工艺**的关系：课程链提供定理排序（学什么、按什么次序学），五阶段框架提供生产工艺（每个定理如何被可信地制造出来）。接口设计三条：

1. **定理清单项即登记单元**：02 篇 T1.1–T1.8、T2.1–T2.5 与 03 篇 P0–P4 的每一项，入库时按阶段⑤登记血缘三元组；课程链的"复用/自建/推迟"三分（02 篇 §3.2）直接映射为三元组的类别字段；
2. **课程段即中间层**：Zp/Qp 课程段的接口定理（ℤ\_p 是 DVR、闭单位球刻画、Hensel 引理）正是 Dedekind 段"局部化 ⇒ DVR"判据的中层接口——课程链的构建顺序（具体 → 抽象）天然满足"接口层只依赖下层接口"；
3. **首个完整走查**：系列 05 篇以阶段 I 的 T1.2（超度量性质）与 T1.3（完备性）为对象，执行了五阶段框架的完整流程（含编译硬门与 `#print axioms` 审计），是本方法论的首个实证案例。

## 9 风险与开放问题

1. **O4.1**（三指标的可计算性）：依赖深度与证明长度的工程测量依赖 import 闭包与内核展开工具，本仓库尚无现成管线；短期以 tactic 步数与人工抽样代理。
2. **O4.2**（阈值校准）：三指标阈值须在阶段④首批目标完成后回填校准数据；当前判据只用于"相对低值拦截"（平凡定理识别），不用于深层定理的正向认证。
3. **O4.3**（01 篇两条文献表述的回溯性勘误）：Flyspeck 超线性维护成本、Metamath 20–30% 可降级两条表述经本轮核验判为对文献的过度引申（§8.2），建议 01 篇下一修订版按 §8.2 措辞修正，提交季度复盘。
4. **语义幻觉纪律**：中间层接口定理是"命题-意图对齐"复核的高发区（Lean Atlas，arXiv:2604.16347）；01 篇 §7 确立的必填项纪律在阶段②强制执行。
5. **双轨复发的温床**：凡新模块 import 旧模块不便时即有自建双轨的冲动（ChernNumber 教训）；阶段②把"双轨检测"列为 CI 检查项（同名结构跨模块扫描）。

## 10 结论

水平扩展的终结不是"少生产"，而是更换生产函数：从以声明数为度量的扁平堆积，换成以"到达深层定理的路径长度"为度量的纵深整合。本文给出的三件套——中间层定理网络（引理工厂模式）、非平凡性三指标、五阶段实施框架——把发展战略 §2.3 的一句话纲领展开为可排期、可验收、可复盘的工程序列；20 篇模块强化论文的横断证据（假公理、零占位、脚手架样板）规定了框架的设计约束，课程链（02/03 篇）提供首个试验场，05 篇的 Zp 实证完成首次走查。从平凡证明到深层定理的距离，不是数量问题，而是结构问题——而结构是可以建造的。
